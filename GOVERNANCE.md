# Project governance

Heyrafiki uses a Benevolent Dictator for Life governance model.

Daniel Moenga is Heyrafiki's Founder and BDFL. He holds final responsibility for the project's long-term direction, product and technical architecture, safety boundaries, public repository scope and release governance.

## How decisions are made

- Contributors propose changes through issues and pull requests.
- Maintainers evaluate proposals for correctness, safety, accessibility, interoperability and fit with the repository's purpose.
- Decisions should be supported by reproducible evidence, a clear user or integration need and the smallest coherent change.
- The BDFL resolves cross-repository decisions and questions where consensus cannot be reached.
- Accepted decisions are recorded in the relevant contract, code, documentation or governance file so the result is inspectable.

## Maintainers and delegation

The BDFL may appoint maintainers and delegate responsibility for repositories or technical areas. Delegated maintainers can review, request changes and merge within that responsibility. The BDFL may revise a delegation when the project's safety, coherence or long-term direction requires it.

## Compatibility and safety

Public contributions do not override Heyrafiki's privacy, clinical safety, security or institutional-control boundaries. Changes to public contracts, supported behavior or release guarantees require migration and compatibility consideration proportional to their impact.

## Governance changes

Material changes to this governance model require the BDFL's approval and a public change to this file.
